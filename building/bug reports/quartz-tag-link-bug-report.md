## Bug: Tag links (`#tag`) resolve to the site root instead of relative to the current page, once the note is inside a subfolder

### Summary

Regular internal links (via `crawl-links`, `markdownLinkResolution: shortest`) correctly resolve at any folder depth. Inline `#tag` links generated by `obsidian-flavored-markdown`, however, only resolve correctly for notes sitting at the content root. As soon as a note is one or more folders deep, its `#tag` links point to the bare domain root instead of to `<baseUrl>/tags/<tag>`, producing a 404.

### Environment

- Quartz version: v5.0.0
- Deployed via GitHub Pages (project page, not user/org page)
- Relevant plugins:
  - `@quartz-community/obsidian-flavored-markdown` (enabled, default options)
  - `@quartz-community/crawl-links` (`markdownLinkResolution: shortest`)
- `baseUrl` in `quartz.config.yaml`: `bodhipaine.github.io/essaying-out-of-the-thickets`

### Steps to reproduce

1. In a note sitting at the content root (e.g. `content/about.md`), add an inline tag: `#example`.
2. In a note sitting one or more folders deep (e.g. `content/essaying/some-folder/note.md`), add the same tag: `#example`.
3. Build and deploy (`npx quartz build`, pushed via the standard GitHub Actions workflow — no custom caching of build output).
4. Visit both published pages and click the `#example` tag link on each.

### Expected behaviour

Both links resolve to:
`https://bodhipaine.github.io/essaying-out-of-the-thickets/tags/example`

(matching the behaviour of ordinary `[[wikilink]]`-style links processed by `crawl-links`, which resolve correctly regardless of the source note's folder depth.)

### Actual behaviour

- The root-level note's tag link resolves correctly.
- The nested note's tag link resolves to:
  `https://bodhipaine.github.io/tags/example`
  which 404s, because it has dropped the `essaying-out-of-the-thickets` subpath entirely.

### Live examples

- Working (note at content root): `https://bodhipaine.github.io/essaying-out-of-the-thickets/about/` — tag links like `#consciousness` correctly point to `.../essaying-out-of-the-thickets/tags/consciousness`.
- Broken (note one+ folders deep): `https://bodhipaine.github.io/essaying-out-of-the-thickets/essaying/don't-believe-what-i-think/xx.-references/🎯-two-minds-by-wendell-berry` — tag links like `#worldview` point to `bodhipaine.github.io/tags/worldview` (404).

### Suspected cause

`crawl-links` appears to correctly compute a relative path based on the actual depth of the source file for ordinary links. The tag-link generation inside `obsidian-flavored-markdown` looks like it may not be doing the same depth-aware calculation — possibly assuming the source file is always at (or near) the content root, so it produces the correct number of `../` hops only when that assumption happens to be true.

### Config for reference

```yaml
configuration:
  baseUrl: bodhipaine.github.io/essaying-out-of-the-thickets
  # ...
plugins:
  - source: "@quartz-community/obsidian-flavored-markdown"
    enabled: true
    options:
      enableInHtmlEmbed: false
      enableCheckbox: true
    order: 30
  - source: "@quartz-community/crawl-links"
    enabled: true
    options:
      markdownLinkResolution: shortest
    order: 60
```
